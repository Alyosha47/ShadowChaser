## 1. What actually shipped and works

**The cloud mode strip (`js/cloudbar.js` + `#cloudbar` in `index.html` + CSS).**
Press `☁` and a strip appears under the overlay buttons carrying the colour bar,
the source credit and a two-cell segmented control, `Average | Now`. This part is
sound and was never the problem.

- The `☁` button keeps its single job — overlay on or off. The strip decides which
  mode that is. **A 3-state cycling button was rejected**: "Now" is unavailable
  offline and outside coverage, so a cycle would frequently contain a dead state,
  either silently skipped or a no-op tap.
- The mode switch **is** the source label, so there is only ever one statement of
  which dataset is showing.
- Cells grey individually with an explanatory `title`, exactly as the shadow button
  does offline.
- **`Average` finally has a legend.** §10.5 justified banding the palette on the
  grounds that "a value can be read off the map without probing" — which was not
  true without a colour bar. The gradient is built from `Cloud.stops()` rather than
  copied, so the bar and the pixels cannot drift apart.
- Adding a third mode later is a third cell, not a redesign.

**`js/cloud.js` changed in three places only, all additive.** It delegates the
button click *if* `CloudBar` exists, stops writing `aria-pressed` *if* `CloudBar`
exists, and exports `enable` / `disable` / `stops`. Delete `cloudbar.js` and the
button reverts to exactly the toggle it always was.

**`js/forecast.js` + `tools/checks/test_forecast.js`** — written early, never wired
into `index.html`, still valid. See §4.

## 2. What does NOT work: the "Now" layer itself

`js/satellite.js` currently stacks four full-disk geostationary layers at full
opacity. **On screen it is unusable**: hard vertical joins between satellites,
mismatched renderings side by side, and gaps where the basemap shows through.

Five architectures were tried and abandoned. **Do not re-attempt any of them.**

| # | Approach | Why it failed |
|---|---|---|
| 1 | Provider imagery as plain raster tiles | Every product is a PICTURE where clear sky is a COLOUR. Replaces the basemap instead of annotating it. |
| 2 | Viewport-shaped canvas, alpha rebuilt in-browser | `map.getBounds()` is meaningless in **globe projection** — image stretched across the planet, landed elsewhere at each zoom. |
| 3 | Fixed whole-world canvas | `animate:false` makes MapLibre snapshot a canvas source **once**, so every later remap updated pixels nobody re-read. Covered the map opaquely. |
| 4 | `addProtocol`, per-tile satellite choice + alpha remap | Geometry finally correct. But GIBS and EUMETSAT render "IR 10.8 µm" with **different greyscale stretches**, so identical cloud got a different alpha either side of a tile edge — visible patchwork. Unfixable by tuning. |
| 5 | Four full-disk layers stacked, full opacity | Current state. Coverage by stacking works (nothing chooses, so nothing chooses wrong), but the four products look nothing like each other. |

**The single lesson under all five:** thresholding continuous brightness cannot
work. Pick a floor and thin cloud vanishes; lower it and the basemap drowns under a
grey veil; and the correct floor differs per provider. That is also what produced
the patchwork.

## 3. THE ANSWER, found at the very end and NOT yet implemented

`github.com/matteason/live-cloud-maps` (CC0, 279 stars) solves this properly, and
**does not stitch satellites at all.**

It pulls **EUMETSAT's own multimission composites**, each requested in two halves
(`bbox=-90,-180,90,0` and `-90,0,90,180`, EPSG:4326) and blitted side by side:

- `mumi:worldcloudmap_ir108` — geostationary ring IR
- `mumi:wideareacoverage_rgb_natural`
- `mumi:wideareacoverage_rgb_dust`

EUMETSAT has already merged the satellites, so **there are no seams to fix.**

**The trick that made his output clean where every ramp of mine was mud:** he does
not threshold one band. He combines products — IR for structure, plus the
natural-colour RGB, where his own comment reads *"Red channel has more detail, blue
channel provides a decent mask when inverted."* Then gamma correction, and the poles
mirrored because the satellites do not see them.

**His finished output is directly usable, no compositing at all:**

```
https://clouds.matteason.co.uk/images/8192x4096/clouds-alpha.png
```

Global, greyscale, **real alpha transparency**, CORS enabled, CC0, four resolutions
(8192×4096 down to 1024×512). Requires attribution: *"Contains modified EUMETSAT
data"*. Equirectangular, so it needs one deterministic reprojection to Web Mercator
— per tile via `addProtocol` is the clean way, since MapLibre then owns geometry.

**The cost: it updates every 3 hours.** The user has already rejected 3-hour-old
data once, so this is his call, not the assistant's.

### The open question worth testing first

Fresh data exists — it is the *merged* product that lags:

| layer | age in the same probe |
|---|---|
| `msg_rss:rgb_natural_nrt` (Rapid Scan, Europe only) | 16:35Z |
| `mtg_fd:rgb_geocolour` | 16:20Z |
| `msg_fes:ir108` | 16:15Z |
| `mumi:worldcloudmap_ir108` (merged) | **12:00Z** |

So: **can his multi-product combination be applied per-satellite instead of to a
pre-merged global image?** That would give ~20-minute-old data with his clean
extraction. Unknown — the per-satellite renderings differ, which is exactly what
broke approach #4. This is the first thing to try.

## 4. Verified facts worth keeping (all checked against live services, not recalled)

**GIBS**
- Serves **WMS as well as WMTS** — `https://gibs.earthdata.nasa.gov/wms/epsg3857/best/wms.cgi`.
- Advertises **1591 layers**; 118 mention cloud. **Every cloud layer is a polar
  orbiter** (MODIS, VIIRS, AIRS, AMSR, SSMI) or TEMPO. **No geostationary cloud
  product exists** — so GIBS cannot cover the Americas or Pacific for cloud.
- Verified working: `GOES-East_ABI_GeoColor`, `GOES-West_ABI_GeoColor` (Level7,
  jpg), `Himawari_AHI_Band3_Red_Visible_1km`, `Himawari_AHI_Band13_Clean_Infrared`.
- **`Himawari_AHI_GeoColor` does not exist.** GeoColor is a CIRA/NOAA product NASA
  only built for the GOES pair.
- **GIBS renders `Himawari_AHI_Band13_Clean_Infrared` through a COLOUR palette** —
  rainbow blobs, not greyscale. "Clean Infrared is greyscale" was an assumption,
  never checked, and it shipped.
- **The catalogue leads publication.** GOES-West advertised a stamp whose image
  404s while GOES-East a second later was fine. Trusting the newest advertised
  frame drops a satellite at random — a hole in the world, and **a hole reads as
  clear sky.** Step back through frames until one loads.
- Timestamps come from DescribeDomains. **Never fall back to `time=default`** — it
  is not necessarily recent.

**EUMETSAT** — `https://view.eumetsat.int/geoserver/wms`, WMS 1.3.0, no key, no
registration, CORS open.
- Advertises **116 layers**.
- `msg_fes:clm` / `msg_iodc:clm` are **cloud masks** — white cloud 52%, blue sea
  12%, green land 12%. A ~1100 distinct-colour count is antialiasing from
  server-side resampling; classify to the nearest of the three and it is clean.
  **0° and Indian Ocean only.**
- Stamps carry **milliseconds** (`…:00.000Z`) where GIBS does not. Reformatting
  invents a time the service has never heard of.

**Both providers**
- WMS 1.3.0 + `CRS=EPSG:3857` takes bbox as minx,miny,maxx,maxy in metres. The
  1.3.0 axis-order flip applies to **EPSG:4326** (lat,lon) — using 4326 without
  swapping returns an empty image and **no error**.
- Pixel read-back needs `crossOrigin='anonymous'`; both send permissive CORS.

**Rejected sources**
- **NOAA GMGSI via LibreWXR** (`api.librewxr.net`, CC-BY-4.0, Rain Viewer v2
  compatible). One request, global, but the mosaic carries **visible brightness
  steps at its own satellite boundaries** — measured as two hard meridional edges,
  ~22°W and over eastern Europe — and ran an hour or more behind.
- **RainViewer satellite** — their own example repo states the free tier is past
  radar only, no satellite.
- **Open-Meteo forecast API** — viable, see below, but a different feature.

**Open-Meteo (for #F2b forecast, still unwired)** — from its own source,
`calculateQueryWeight()`: **every location costs at least one call, and locations
sum.** Batching 400 points into one request does not make it one call. 600/min,
5,000/hr, 10,000/day, per-user-IP because calls run in the browser. Consequence:
forecast is a **zoomed-in** field by construction — 0.5° over a 120°×40° path is
19,200 points, two days of quota for one render.

## 6. Process failures, recorded because they cost the whole session

- **Guessing instead of enumerating.** EUMETSAT's masks were found by listing all
  116 layers. For GIBS, six layer names were *guessed*, all missed, and the wrong
  conclusion drawn — until the same enumeration was finally run and settled it.
  **Enumerate. Never guess a layer name.**
- **A filter that contradicted its own ranking.** `mask` sat in a `SKIP` regex from
  an early version while a later edit promoted cloud masks to rank 0. The skip list
  won silently, and `msg_fes:clm` never appeared in 116 layers. **Exclusions must be
  narrower than inclusions, and widening one means re-checking the other.**
- **Tests that grepped the file's own prose.** An assertion "nothing is proxied"
  matched the comment *warning against* proxying. Fixed by asserting against a
  comment-stripped copy — then the same class of error recurred twice more.
- **Deleting code with regexes**, twice, leaving orphaned continuation lines and
  broken syntax both times. Delete by matching braces, or by markers.
- **Diagnosing from one detail while ignoring the rest of the same screenshot.** A
  seam was confidently attributed to the day/night terminator; the user pointed out
  a second seam in the same image, which ruled that out immediately.
- **Shipping unverified builds.** Four full deploys of the "Now" layer, each costing
  the user a manual multi-file upload, none of them checked beyond passing tests.
  Probe pages cost one file and no BUILD bump — **use them before touching the app.**
- **Ignoring the standing rule.** `TODO.md` says use the renderer's API before
  hand-rolling. Projection and tiling were hand-rolled twice before `addProtocol`
  was reached.
